## 一、事故复现口径（先复现，后修复）

批重映中断后续跑出现：

1. **cursor 跳号**：旧实现窗口取完按 `last_cursor + limit` 算术推进，与实际处理到的最后一行 `inbound_keys.id` 脱钩。
2. **游标先于处理提交**：`cursor_ledger` 先落账并 commit，正式实体后写；处理中途报错时账已前进、实体未进正式区。
3. **假完成**：完成旗只看“窗口取空”，不核应收键数；存在未映旧键时状态仍转“已完成”，正式增量与应收键数对不上。
4. **无批锁**：两路同 batch 可同时推进 cursor，重复写正式实体，后到者不记争用。

复现夹具：`fixtures/inbound_batch.json`（10 键，limit=3，故障点 `fault_on:OLD-K04`）。
红测：`tests/test_cursor_skip.py`，其中两条规定红测——
`test_cursor_skip_false_completion`（漏映却完成绿）、
`test_batch_lock_contention`（抢批争用）——须先见红，方可改写游标写路径。

## 二、路径择定（甲乙互斥，不得混用）

| 路径 | 口径 | 本次是否采用 |
|----|------|------------|
| **甲：强制游标** | 续跑必须携带上次 cursor；缺失或不符则整笔拒绝（HTTP 400），正式零增、cursor 账不动 | **采用（锁定）** |
| 乙：全量幂等 | 允许全量重扫，已映键幂等跳过并写 skip 审计；审计失败则 cursor 与增量回滚 | 互斥，不采用 |

**择定：甲路径。锁定日期 2026-11-20，当天禁止改口。**

选择依据：现网链路本就是 cursor 查询续跑模型，甲路径贴合现状、改动面集中；其“缺 cursor 整笔拒绝、正式零增”是更强不变量，终态天然无 skip 可查。乙路径需引入全量重扫与 skip 审计写/回滚分支，与甲互斥，本次不启用、不混用。

### 甲路径硬规则

1. 每次 `/api/batch/remap` 请求必须携带 `resume_cursor`，且必须等于 `cursor_ledger` 中该 batch 的末条 `last_cursor`；不符一律 400 拒绝，**整笔不写**（正式实体零增、cursor 账零前进、回执不换版）。
2. 首批（新建批次）的合法 cursor 为 0。
3. 新 cursor 取值必须是本窗实际处理到的最后一行 `inbound_keys.id`（真实游标），禁止任何 `cursor + limit` 算术累加。
4. 单窗处理为**单事务**：锁、ledger、正式实体、processed 标记、批次状态、回执在同一事务内提交；任一键处理失败整体回滚，cursor 与正式增量都不前进（故障注入点抛错即回滚）。
5. 完成旗转“已完成”的唯一条件：`processed=1` 计数等于 `total_keys`（应收键数），且正式实体计数同数；窗口取空但有未映键时保持“进行中”。

## 三、批锁与争用

1. 两路同 batch 推进 cursor 必须占批锁（表 `batch_locks`，主键即 `batch_id`）。
2. 占锁采用 `INSERT` 占位；后到者占锁失败即返回 HTTP 409，并在 `lock_events` 写一条 `event='争用拒绝'`，**只记争用，不做任何业务写**。
3. 事务结束（提交或回滚）后在 finally 中释放本持有者的锁；异常路径同样释放，不得留死锁。
4. 连接设 `busy_timeout=3000`，锁等待有界。

## 四、五处同态

以下五处对同一 batch 的计数/状态必须同态，互证页与回执仅展示账实，不另设进度台、不手算百分比：

| # | 处 | 同态字段 |
|---|----|---------|
| 1 | cursor 账 `cursor_ledger` | 末条 `last_cursor` = 实际末处理行 id |
| 2 | 正式实体 `formal_entities` | 该 batch 行数 = 已处理键数 |
| 3 | skip 审计 `skip_audit` | 甲路径下恒为 0 行 |
| 4 | 批回执 `batch_receipts` | formal/skip/expected 与上各处一致，状态随批次 |
| 5 | 互证页 `/api/batch/proof` | 五值对账一致，不一致即不允许“已完成” |

只改进度条/百分比而不修写路径，判失败。
